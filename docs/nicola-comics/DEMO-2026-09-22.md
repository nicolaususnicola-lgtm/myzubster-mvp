## 2. Demo tecnica

### Catalogo

```text
GET https://myzubster-mvp.onrender.com/api/comics
```

Risultato atteso: tre tavole del pilot.

### Gallery via adapter Zorgax

```http
POST https://myzubster-mvp.onrender.com/api/zorgax/ask
Content-Type: application/json

{
  "question": "Mostrami i fumetti di Nicola",
  "action": "gallery"
}
```

### Detail

```json
{
  "question": "Mostrami la scheda della tavola 01",
  "action": "detail",
  "comic_id": "n4k48-comic-001"
}
```

### Candidate

```json
{
  "question": "Quale candidata NFT?",
  "action": "candidate"
}
```

### Next steps

```json
{
  "question": "Quali sono i prossimi passi?",
  "action": "next_steps"
}
```

## 3. Percorso da mostrare durante l'incontro

`richiesta fumetti → gallery → detail/card → immagine → candidate → rights/on-chain status → next_steps`

Durante la demo evidenziare sempre la differenza tra dati verificati e attività ancora da completare.

## 4. Stato NFT e diritti

`n4k48-comic-001` è soltanto `NFT_CANDIDATE / PROPOSED_FOR_REVIEW`.

- `rights_status`: `TO_VERIFY`.
- Nessun mint dichiarato.
- `contract_address`, `token_id`, `transaction_hash`, `network` e `metadata_uri` devono restare vuoti finché non esiste una prova on-chain verificabile.
- Il pilot non espone wallet, pagamenti, private key, seed phrase o funzioni di mint.

## 5. Cosa chiedere al team MyZubster

1. Collegare il Zorgax pubblico all'endpoint HTTPS del pilot.
2. Definire il mapping delle intenzioni alle azioni `gallery`, `detail`, `candidate`, `next_steps`.
3. Definire eventuale autenticazione/autorizzazione come secret dell'ambiente, senza inserirla nel repository.
4. Eseguire e documentare una prova end-to-end dal Zorgax pubblico.
5. Concordare il processo per verifica di provenienza e autorizzazioni della candidata NFT.
6. Stabilire i criteri per passare da `PROTOTYPE` a `PILOT` e, in futuro, per un eventuale proof NFT verificabile.

## 6. Confine della demo

Questa demo dimostra il catalogo, la galleria, le schede, l'adapter e il deployment pubblico del lato Nicola Comics. Non deve essere presentata come prova di mint o come prova del collegamento upstream al Zorgax pubblico finché tale integrazione non viene verificata end-to-end.
